# 부채 공격 VFX 테스트

`Assets/Test/FanAttackVfx/Scenes/Test_FanAttackVfx.unity`를 열고 Play합니다. 원본 MountainPass 씬의 사본이며, 편집 가능한 전투 설정도 이 폴더에 복사했습니다. 모델·애니메이션 등 기존 에셋은 읽기 전용으로 참조합니다.

시작 위치에는 8m 바람 전체를 가리지 않고 확인할 수 있는 평평한 `Test_PreviewStage`를 추가했습니다. 복사본의 높이 안개는 효과의 색과 먼지를 확인하기 위해 껐습니다. 기존 산길 환경은 복사본에 남아 있습니다.

## 조작

- 시작하면 인트로를 넘기고 부채를 꺼냅니다.
- 숫자 **1 / 2 / 3**: 해당 공격. **좌클릭 / J**: 기존 연계 공격. **WASD**: 이동. **마우스**: 시점. **휠**: 거리.
- **Space**: 구르기. 점프 후 접지 시 먼지가 한 번 퍼지고, 구르는 경로에 먼지가 이어집니다.
- `Test_FanAttackVfx` 오브젝트의 컴포넌트 메뉴 → `미리보기`에서도 각 공격을 재생할 수 있습니다.
- `Show Original Ranges`를 켜면 기존 바닥 부채꼴과 VFX의 범위를 비교할 수 있습니다.

## 조절하는 곳

`Settings/Test_FanAttackVfxProfile.asset`을 선택합니다. Play Mode에서도 변경 내용을 즉시 반영합니다. **설정 에셋의 변경은 Play 종료 후에도 유지**되므로 값을 되돌리려면 실행 전에 에셋을 복제해 두세요.

| 항목 | 역할 |
| --- | --- |
| Attack 1 / 2 / 3 → Start/End Frame | 원본 FBX 프레임 기준 이펙트 표시 구간. 애니메이션 배속을 바꿔도 동기화됩니다. |
| Radius / Angle / Inner Radius | 공격 반경, 전체 각도, 몸 주변을 비울 거리 |
| Plane | 수평 휘두르기 / 세로 내려치기 선택 |
| Pivot Height / Start Pitch / Roll | 세로 궤적의 중심 높이, 시작 각도, 옆 기울기. 뒤쪽만 더 펼칠 때는 Start Pitch와 Angle을 같은 양만큼 늘립니다. |
| Height / Height Offset / Height Multiplier | 수평 궤적의 손 높이 곡선과 추가 보정. 세로 궤적은 Pivot Height로 조절합니다. |
| Motion Progress / Reverse | 모션에 따른 궤적 진행률과 휘두르는 방향 |
| Hit Start/End Frame | 타격 구간. 음수이면 궤적의 표시 구간과 동일 |
| Tail Length / Fade Seconds | 궤적의 남는 길이와 사라지는 시간 |
| Color / Intensity | 색상, 투명도, 밝기 |
| Attack 1 Wind / Wind | 1타 / 3타 바람의 독립적인 표시 구간·범위·높이·파티클 설정 |
| Forward Scale | 바람 폭은 유지하고 전방 길이만 늘립니다. 1타 기본값 1.3 |
| Travel Progress | 시간에 따른 바람 이동 거리 곡선. 초반에 급하고 끝에 완만할수록 빠르게 출발해 천천히 끝납니다. 시각 효과와 원격 판정이 함께 사용합니다. |
| Conform To Ground | 켜면 지형 높이를 따라갑니다. 1타는 꺼 두어 완전한 평면을 유지합니다. |
| Dust / Front Share / End Burst Count | 먼지 설정 / 전방 발생 비율 / 끝의 원호에 발생하는 추가 먼지 개수 |

1타는 **19–28f의 세로 궤적**과 **25–38f의 평평한 바람**입니다. 궤적 시작을 2f 앞당기고 모션 진행률을 다시 샘플링했습니다. 반경 2.45m, 안쪽 반경 **0.45m**를 사용합니다. 이미지로 요청한 후방 확장은 **Start Pitch 65° → 110°, Angle 100° → 145°**로 적용했습니다. 앞쪽 끝인 -35°는 유지하면서 시작 쪽만 뒤로 45° 더 펼쳤고, **Tail Length 1**로 확장된 잔상이 끝까지 이어지도록 했습니다. 직접 판정도 같은 각도와 19–28f 구간을 사용합니다. 바람은 원래 반경 3m·35°에 **전방 배율 1.3**을 적용해 정면 끝이 **3.9m**에 도달합니다. 폭과 평면 형태는 유지합니다.

2타는 **3m·155°, 28–34f, 왼쪽 → 오른쪽**입니다. 원래의 40–58f는 부채를 회수하는 구간이어서 느리고 반대로 보였습니다. 실제 공격 구간을 다시 샘플링했고, 판정도 궤적의 진행 방향을 따라갑니다.

3타는 **3m·210° 궤적 + 8m·35° 바람, 20–40f**입니다.

1·3타 바람은 거리 곡선으로 감속합니다. 전체 시간의 25%에 거리의 약 52%, 50%에 81%, 75%에 95%를 이동하고 마지막 부분은 천천히 끝납니다. 회오리 입자의 출발 속도도 진행 시간에 따라 낮아지고, 이미 생성된 입자도 수명 후반에 감속합니다. 전방 먼지와 원격 판정은 같은 이동 거리를 따릅니다.

궤적은 3D 메쉬와 전용 URP 셰이더로 구성했습니다. 바람에는 별도 돌풍 셰이더와 회오리 텍스처 파티클을 사용해 밝은 칼날 모양의 궤적과 구분했습니다. 먼지는 바람 양옆과 움직이는 전방에 발생하며, 끝까지 도달하면 최종 원호 전체에 추가로 발생합니다. 지면은 Raycast로 찾고 절벽처럼 지면이 없으면 먼지를 생략합니다.

궤적의 방사형 이음선은 반복 텍스처의 양 끝 무늬가 달라 생기던 문제였습니다. `Test_T_WindFlow`의 노이즈와 가는 결을 두 축 모두 주기적으로 생성하도록 수정했고, 반복 경계의 압축 오차를 피하도록 이 텍스처만 무압축으로 임포트합니다. 기존 텍스처와 GUID를 유지하며, 1·2·3타 궤적에 함께 반영됩니다.

**테스트 씬의 `Test_FanAttackHitDetection`이 실제 피해 판정을 담당**합니다. 기존 `PassPlayerCombat` 컴포넌트는 사본에서만 비활성화했습니다. 직접 판정은 궤적의 반경·안쪽 반경·방향·진행률을, 원격 판정은 바람의 출발 위치·전방 배율·감속 곡선을 읽습니다. 바람은 발사 후 캐릭터가 돌아도 출발 방향을 유지합니다.

같은 공격에서 한 대상은 **직접 타격 1회 + 바람 원격 타격 1회**를 받을 수 있으며, 같은 프레임에도 두 피해가 적용됩니다. 콜라이더가 여러 개여도 각 채널은 한 번만 적용합니다. 2타에는 바람 VFX가 없으므로 직접 타격만 있습니다. 테스트 씬의 적 `PassHealth`는 공유 피격 대기(`Hit Recovery`)를 0으로 설정해 두 피해가 서로 막히지 않게 했습니다. 중복 방지는 각 채널의 기록이 담당하며, 명시적인 무적 상태는 그대로 적용합니다. 새로운 테스트 적을 추가할 때도 Hit Recovery를 0으로 설정하세요. 플레이어의 피격 대기와 원본 체력 스크립트는 변경하지 않았습니다.

## 피해량과 비중

Hierarchy의 **Player → Test_AttackDamageSettings**를 선택합니다. 렌더러나 콜라이더가 없는 빈 오브젝트이며, `Test_FanAttackDamageSettings` 컴포넌트에서 공격별 값을 조절합니다.

| 항목 | 계산 |
| --- | --- |
| Base Damage | 각 공격의 기준 피해량 |
| Direct Weight | 부채 직접 피해 = 기준 피해량 × 이 비중 |
| Wind Weight | 바람 원격 피해 = 기준 피해량 × 이 비중 |

초기값은 1타 **22 × (직접 0.7 / 바람 0.3)**, 2타 **28 × (직접 1 / 바람 0)**, 3타 **40 × (직접 0.7 / 바람 0.3)**입니다. 두 피해가 모두 맞으면 각각 22 / 28 / 40이며, 바람만 맞으면 해당 비중의 피해만 적용됩니다. 비중 합계는 자동 정규화하지 않습니다. 0으로 설정한 채널은 피해를 주지 않습니다. 이 오브젝트는 Play Mode에서도 즉시 반영되며, **Play 중 바꾼 오브젝트 값은 종료 시 복원**됩니다. 유지할 값은 Edit Mode에서 설정하세요.

## 에셋과 재샘플링

- `Meshes`: 각 공격과 바람의 메쉬 에셋
- `Materials`, `Shaders`: 궤적·바람·흙먼지 렌더링
- `Textures`: 교체 가능한 바람결과 흙먼지 PNG. 원본은 최대 512px, 임포트 제한은 모든 대상 플랫폼에서 1024입니다.
- `Prefabs/Test_FanAttackVfx.prefab`: VFX 구성을 묶은 프리팹. 다른 테스트 씬에 배치하면 캐릭터를 자동으로 찾습니다.
- `Scripts`: 프레임 동기화 / 메쉬 생성 / 파티클 / 설정을 역할별로 분리했습니다.
- `Test_FanAttackHitDetection`: 테스트 전용 피해 판정. `LastHitFrame`, `LastHitAttack`, `HitsLanded`, `DirectHitsLanded`, `WindHitsLanded`로 실행 결과를 확인할 수 있습니다.
- `Cheon > Tests > Fan Attack VFX > 공격 모션 다시 샘플링`: 테스트 씬의 애니메이션에서 손의 이동을 다시 추출합니다. 높이·진행률·방향을 갱신합니다.

모션 또는 표시 프레임을 크게 바꾼 뒤 재샘플링하면 높이와 진행률을 다시 맞출 수 있습니다. 반경·각도·색상은 별도로 조절합니다. 원본 씬·스크립트·FBX에는 쓰지 않습니다.

## 구르기 착지 먼지

`Settings/Test_RollDustProfile.asset`에서 공격 먼지와 별도로 조절합니다. 모션을 샘플링해 **12f 착지 / 12–23f 구르기 접촉**으로 맞췄습니다. 실제 지면이 있는 경우에만 발생하며, 점프 구간이나 일어선 뒤에는 새 입자를 만들지 않습니다. 파티클은 월드 공간에 남아 자연스럽게 사라집니다.

| 항목 | 역할 |
| --- | --- |
| Landing Frame / End Frame | 원본 FBX 기준 착지·구르기 접촉 구간 |
| Landing Count / Radius / Outward Speed | 착지 순간 퍼지는 먼지의 양·범위·속도 |
| Particles Per Second / Per Meter | 구르는 동안 시간·이동 거리에 따른 먼지 발생량 |
| Trail Width / Drift | 뒤에 남는 먼지의 폭과 흐름 |
| Size / Lifetime / Opacity / Color | 크기·수명·투명도·색 |
| Ground Distance / Mask / Offset | 접지 확인 거리·지면 레이어·바닥에서 띄울 높이 |

`Prefabs/Test_RollDust.prefab`과 `Scripts/Test_RollDust.cs`가 담당합니다. 기존 먼지 텍스처와 머티리얼을 재사용했으며, 원본 이동·구르기 스크립트와 애니메이션은 수정하지 않았습니다. 필요하면 `Cheon > Tests > Fan Attack VFX > 구르기 착지 먼지 적용`으로 사본 씬에 다시 연결할 수 있습니다.

Play Mode에서 점프 구간(9f)은 발생량 0, 약 12.5f의 착지는 1회, 17.5f에는 착지 입자 18개와 경로 입자 16개가 발생하는 것을 확인했습니다. 종료 후 잔여 입자 수는 0으로 돌아왔고, 구르기 배속을 1.25에서 2.5로 바꿔도 약 12f에 한 번 발생했습니다. [구르기 먼지 미리보기](Test_RollDust.png)

## 검증

Unity 6000.3.14f1 / URP 17.3.0에서 컴파일과 에셋 검사를 통과했습니다. 이번 변경은 실제 Play Mode에서 다음을 확인했습니다.

- 1타 0.8m·1.9m 대상: 직접 **15.4**와 바람 **6.6**, 합계 **22**. 3.7m 대상: 바람 **6.6**만 적용. 4.3m와 옆쪽 대상: 피해 없음.
- 2타 왼쪽·중앙·오른쪽: 약 **29.1 / 31.0 / 33.0f**에 직접 **28**씩 한 번 적용.
- 3타 가까운 대상: 바람 **12**와 직접 **28**, 합계 **40**. 옆쪽 대상: 직접 **28**만, 7.8m 대상: 바람 **12**만, 8.7m 대상: 피해 없음.
- 프레임이 18f에서 30f로 건너뛰는 조건: 직접·바람 피해가 **같은 30f에 모두 적용**됐으며, 대상에 콜라이더를 추가해도 채널당 한 번을 유지했습니다.
- 피해 설정을 기준 100 / 직접 0.25 / 바람 0으로 변경: 직접 **25**만 적용됐습니다. 검증 후 초기값으로 복원했습니다.

검증 대상은 Play Mode에서만 생성했고 씬에는 남기지 않았습니다. 콘솔에 새 오류가 없으며 원본 씬·이동·애니메이션·전투 스크립트의 해시가 작업 전과 같습니다.

후방 확장과 이음선 수정 후 측면의 실제 재생 화면을 확인했습니다. 텍스처의 좌우·상하 경계 픽셀 차이는 **0/255**이며, 이전에 보이던 두 개의 방사형 경계가 사라졌습니다. 새로 확장된 후방 상단 영역의 대상에도 직접 피해 **15.4**만 한 번 적용되는 것을 확인했습니다.
