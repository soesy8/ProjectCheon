# 보스 패턴 진단

대상: Assets/Scenes/MountainPass/MountainPass_Optimized.unity
코드·씬 설정은 수정하지 않고 진단했다.

## 실행 관찰

플레이어 무적·입력 정지 상태에서 실제 AI를 120초 관찰했다. 패턴 메서드 직접 호출이나 쿨타임·AI 상태 강제 변경은 사용하지 않았다.
- 본체 이동 점프 9회, 엎어지기 7회, 전방 연속 폭발 9회, 소환 1회.
- 소환된 잡몹 2마리 생존. 협동 시작 0회, 완료 0회, 진행 중 취소 0회.
- 소환 회복이 끝날 때 잡몹들은 이미 방향 정렬에 진입했다. 보스는 다음 프레임 폭발을 선택했다.
- 연계 검토 가능 시점 표본에서는 동시 참가 가능 잡몹 2마리를 확보하지 못했다.
- 실행 종료 후 콘솔 오류 0건, 활성 씬 미저장 변경 없음.

## 확인한 구조 문제

CanJoinLinkedAttack는 잡몹의 Idle·미예약·점프 쿨타임 완료를 동시에 요구한다. 그러나 잡몹은 점프 쿨타임이 끝나면 자신의 ChoosePattern에서 곧바로 일반 공격으로 진입한다. 본체도 Idle에서만 연계를 검토하므로 독립적으로 행동하는 두 잡몹의 짧은 준비 완료 구간과 본체의 선택 시점이 모두 일치해야 한다. 참가자를 미리 순차 예약하는 단계가 없다.

본체 일반 엎어지기와 연계가 FallReadyAt을 공유하므로, 연계 참가자를 확보하지 못해 일반 엎어지기를 선택하면 연계도 본체 공격 종료와 추가 쿨타임을 기다리게 된다.

## 본체 선택 순서

Idle이고 전투가 진행 중이며 최초 대기 1초가 끝난 뒤 평가한다. 진행 중인 연계나 예약이 있으면 새 패턴을 선택하지 않는다.
1. 방향 정렬: 정면에서 45도 초과, 연속 정렬 3회 미만. 0.5초 동작, 착지 후 1초 대기. 이 분기에 걸리면 다른 패턴도 대기한다.
2. 잡몹 소환: 본체 이동 점프 누적 3회 이상, 생존 잡몹 0마리, 전멸 후 15초 경과, 좌우 소환 위치가 안전할 때. 선·후딜 각 1초. 최초 소환은 전멸 대기 없이 가능. 점프 횟수는 소환 시 초기화하지 않는다.
3. 협동공격: 사용 활성화, 참가 가능한 잡몹 2마리 동시 확보, 연계 쿨타임과 본체 엎어지기 쿨타임 모두 완료, 안전한 순간이동 위치 확보. 연계 종료·진행 중 취소 후 6초 대기.
4. 전방 연속 폭발: 활성화 및 쿨타임 완료이고 폭발 선호 상태이거나 플레이어 거리가 약 12.22m 초과. 종료 후 8초 대기. 2m 간격 5지점, 0.15초 간격.
5. 일반 엎어지기: 본체 엎어지기 쿨타임 완료, 플레이어 거리 약 13.21m 이내. 후딜 완료 후 무작위 4~6초 대기.
6. 이동 점프: 점프 쿨타임 완료와 안전한 착지점 확보. 최대 이동 10m, 플레이어 주변 목표 간격 1.75~3m. 후딜 완료 후 3초 대기.
7. 전방 연속 폭발 재검사: 앞의 엎어지기·점프를 고르지 못하면 폭발이 선호 상태가 아니어도 사용 가능할 때 선택한다.

전투 시작·점프 시작·엎어지기 시작에 폭발 선호가 켜지고, 폭발을 쓰면 꺼진다.
방향 정렬 3회 연속 사용 뒤에는 소환·협동을 건너뛰고 일반 공격을 우선한다.
체력 비율에 따른 2페이즈나 패턴 확률 가중치는 없다.

## 잡몹과 협동 세부 조건

잡몹 자체 선택 순서: 방향 정렬 → 엎어지기(약 3.30m 이내) → 이동 점프. 점프 대기 1.5초, 엎어지기 대기 4~6초. 폭발·소환은 사용하지 않는다.
협동 순서: 0.25초 순간이동 → 첫 점프 전 1초 대기 → 잡몹 점프 시작을 0.5초 간격으로 명령 → 마지막 착지 0.5초 후 본체 내려치기 시작.
잡몹 사망·비활성화·순간이동 실패·착지 시작 및 완료 시간 초과 시 연계가 취소된다.
필요 잡몹 수와 최대 소환 수가 모두 2여서 1마리만 죽어도 연계는 불가능하다. 재소환은 생존 잡몹이 0이 된 뒤 15초가 지나야 한다.

## 개선 방향

본체가 연계를 준비할 때 유휴 잡몹을 먼저 예약하고, 점프 쿨타임은 예약 이후 실제 점프 명령에서 기다리도록 분리하는 것이 핵심이다. 두 잡몹의 준비를 유한 시간 기다리는 조정 단계도 필요하다. 쿨타임 수치만 줄이는 것으로는 동시 Idle 조건 충돌이 사라지지 않는다.

## 진단 중 에디터 복구

초기 임시 기록 스크립트가 Unity 객체를 일반 JSON으로 재귀 직렬화하여 스택 오버플로를 발생시켰다. Unity 직렬화기로 기록 방식을 수정했다. 복구용 씬 백업을 보관했고 사용자가 에디터를 재실행한 후 위 자연 발동 검증을 완료했다. 현재 에디터 연결과 씬은 정상이다.
